# 1. Data model

PostgreSQL 16 or later (NFR-D8). The DDL below is illustrative: it fixes names, keys, constraints and indexes; column lists may gain fields during implementation. Migrations are versioned SQL files applied by `goose` (NFR-D4); queries are written in SQL and compiled by `sqlc`.

## 1. Conventions

- Primary keys are `uuid` (UUIDv7, generated by the application). Timestamps are `timestamptz`.
- Every content table has `user_id uuid not null` and a **composite unique key `(user_id, id)`**. Child tables reference the parent through `(user_id, parent_id)`, so the database itself refuses cross-user references (SEC-ISO-4).
- Mutable entities have `version integer not null default 1` and `updated_at`.
- Extensions: `unaccent`, `pg_trgm`. Nothing that exists only in newer PostgreSQL versions is used.
- Content tables are under row-level security (see [README](README.md) §3).

## 2. Users, sessions and tokens

```sql
create table users (
  id                 uuid primary key,
  username           text not null,                 -- login identifier, case-insensitive
  display_name       text not null,
  email              text,                          -- informational only (AUTH-U2)
  status             text not null default 'pending'
                     check (status in ('pending','active','disabled','deleting')),
  is_admin           boolean not null default false,
  password_hash      text,                          -- null until activation (AUTH-U8)
  timezone           text not null default 'UTC',   -- IANA name (CORE-R2)
  settings           jsonb not null default '{}',   -- grouping window, muted notices
  change_seq         bigint not null default 0,     -- per-user change feed counter (§5)
  created_at         timestamptz not null default now(),
  updated_at         timestamptz not null default now(),
  version            integer not null default 1
);
create unique index users_username_key on users (lower(username));
create unique index users_single_admin on users (is_admin) where is_admin;   -- AUTH-U7, SEC-AUTH-13
```

`status = 'pending'` means no password yet (new account, or reset by activation link). Only `active` users can authenticate, ingest or have working share links (SEC-BOT-13, CORE-SH5).

```sql
create table sessions (
  id                         uuid primary key,
  user_id                    uuid not null references users(id) on delete cascade,
  client_kind                text not null check (client_kind in ('web','native')),
  label                      text not null,           -- "Firefox on Linux", from User-Agent
  created_at                 timestamptz not null default now(),
  last_refreshed_at          timestamptz not null default now(),
  expires_at                 timestamptz not null,    -- sliding (AUTH-C9)
  absolute_expires_at        timestamptz not null,
  refresh_generation         integer not null default 0,
  previous_valid_until       timestamptz,             -- grace window for the previous generation (SEC-AUTH-7)
  revoked_at                 timestamptz,
  revoked_reason             text
);
create index sessions_user on sessions (user_id) where revoked_at is null;
```

Access and refresh tokens are **not stored**: they are MAC-derived from `(session id, generation or expiry)` with a server key, and validated by recomputation plus a lookup of the session row (see [03-auth.md](03-auth.md) §2).

```sql
create table user_tokens (                    -- activation links
  id          uuid primary key,
  user_id     uuid not null references users(id) on delete cascade,
  kind        text not null check (kind in ('activation')),
  token_hash  bytea not null unique,          -- sha256 of a 192-bit random token
  expires_at  timestamptz not null,
  used_at     timestamptz,
  created_by  uuid references users(id) on delete set null
);

create table pairing_codes (                  -- chat linking (AUTH-B3)
  id               uuid primary key,
  user_id          uuid not null references users(id) on delete cascade,
  code_hash        bytea not null unique,     -- sha256 of the 8-character code
  bot_instance_id  uuid,                      -- optional restriction to one instance
  bot_type         text not null,
  expires_at       timestamptz not null,
  used_at          timestamptz
);

create table auth_throttle (                  -- login / pairing-code throttling across replicas (SEC-AUTH-2)
  key           text primary key,             -- 'acct:<lower username>' | 'ip:<addr>' | 'pair:<bot instance>:<identity>'
  failures      integer not null,
  blocked_until timestamptz,
  updated_at    timestamptz not null
);
```

## 3. Bots and linked identities

```sql
create table bot_instances (
  id               uuid primary key,
  type             text not null,             -- 'matrix', ...
  name             text not null unique,
  identity_domain  text not null,             -- e.g. the homeserver domain; identities must match (SEC-BOT-5)
  status           text not null default 'active' check (status in ('active','disabled')),
  last_seen_at     timestamptz,               -- heartbeat (WEB-12 "bot status")
  created_at       timestamptz not null default now()
);

create table bot_credentials (                -- several may be valid during rotation (AUTH-B1)
  id               uuid primary key,
  bot_instance_id  uuid not null references bot_instances(id) on delete cascade,
  client_id        text not null unique,
  secret_hash      bytea not null,            -- sha256 of a 256-bit random secret
  scopes           text[] not null default '{ingest,deliver}',
  created_at       timestamptz not null default now(),
  disabled_at      timestamptz
);

create table external_identities (
  id               uuid primary key,
  user_id          uuid not null references users(id) on delete cascade,
  bot_instance_id  uuid not null references bot_instances(id),
  bot_type         text not null,             -- denormalised for the uniqueness rule below
  external_user_id text not null,             -- e.g. '@robin:example.org'
  conversation_id  text,                      -- current DM room, for deliveries (BOT-12)
  reminder_target  boolean not null default false,
  linked_at        timestamptz not null default now()
);
-- an identity belongs to at most one user, across all instances of a type (AUTH-B4, SEC-BOT-6)
create unique index identities_unique on external_identities (bot_type, external_user_id);
create unique index identities_user_id on external_identities (user_id, id);
```

Unlinking deletes the row. Ingest rejects any event older than `linked_at` (MX-10, enforced in Core so that every bot gets it).

## 4. Content

### 4.1 Pages, categories, notes

```sql
create table pages (
  id uuid primary key, user_id uuid not null references users(id) on delete cascade,
  name text not null, position text not null collate "C",
  archived_at timestamptz, created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(), version integer not null default 1,
  unique (user_id, id)
);

create table categories (
  id uuid primary key, user_id uuid not null,
  page_id uuid not null, name text not null, position text not null collate "C",
  created_at timestamptz not null default now(), updated_at timestamptz not null default now(),
  version integer not null default 1,
  unique (user_id, id),
  foreign key (user_id, page_id) references pages (user_id, id) on delete cascade
);

create table notes (
  id            uuid primary key,
  user_id       uuid not null references users(id) on delete cascade,
  category_id   uuid,                                   -- null = Inbox
  position      text collate "C",                       -- fractional key; null while in the Inbox
  state         text not null default 'active' check (state in ('active','deleted')),
  deleted_at    timestamptz,
  created_at    timestamptz not null,                   -- platform timestamp of the first message (CORE-N18)
  received_at   timestamptz not null default now(),
  updated_at    timestamptz not null default now(),
  version       integer not null default 1,
  unique (user_id, id),
  -- SET NULL with a column list (PostgreSQL 15+): only category_id is nulled, never user_id, which is part of the key.
  -- Do not "simplify" to plain SET NULL: that would try to null user_id. A trigger clears position (see below).
  foreign key (user_id, category_id) references categories (user_id, id) on delete set null (category_id),
  check ((category_id is null) = (position is null))
);
create index notes_board  on notes (user_id, category_id, position) where state = 'active' and category_id is not null;
create index notes_inbox  on notes (user_id, created_at desc, id)   where state = 'active' and category_id is null;
create index notes_trash  on notes (user_id, deleted_at desc)       where state = 'deleted';
```

- **Inbox** is `category_id is null`, ordered by `created_at desc` (design decision D1). It has no position.
- **Dismissing** sets `state = 'deleted'` and `deleted_at`; `category_id` and `position` stay, so **restore** is just setting `state = 'active'` again and the note returns to its previous place (CORE-N6, CORE-N7). Deleting a category sets `category_id` to null on its notes through the foreign key; a trigger clears `position` in the same statement. An active note then lands in the Inbox, and a deleted one restores into the Inbox (CORE-P4).
- **Trash view** shows the previous category name by joining `category_id` (null = "Inbox").
- **Moving into a category** carries `before_id`/`after_id` neighbour hints (see §7); the server generates the position key.

### 4.2 Note parts and history

```sql
create table note_parts (
  id              uuid primary key,
  user_id         uuid not null,
  note_id         uuid not null,
  ordinal         integer not null,                     -- order within the note
  kind            text not null check (kind in ('text','attachment','failed_attachment','unsupported')),
  text            text,                                 -- Markdown, for 'text' and 'unsupported'
  attachment_id   uuid,
  failed_filename text, failed_size bigint, failed_reason text,   -- CORE-A9
  attach_reason   text not null check (attach_reason in ('first','reply','thread','media-adjacency','app')),
  related_part_id uuid,                                 -- explicit relation to a dismissed note's part (GRP-7)
  created_at      timestamptz not null,                 -- platform timestamp
  text_edited_at  timestamptz,                          -- last edit time, either origin (EDT-5)
  source_bot_instance_id uuid,
  source_identity_id     uuid,
  source_conversation_id text,
  source_message_id      text,
  source_part_index      smallint,
  unique (user_id, id),
  unique (note_id, ordinal) deferrable initially deferred,
  foreign key (user_id, note_id) references notes (user_id, id) on delete cascade,
  foreign key (user_id, attachment_id) references attachments (user_id, id)
);
-- find the part(s) a later edit or delete refers to (EDT-1, EDT-6)
create unique index parts_source on note_parts
  (source_bot_instance_id, source_conversation_id, source_message_id, source_part_index)
  where source_message_id is not null;
-- "the sender's previous note in this conversation" (GRP-2)
create index parts_conv_recent on note_parts (source_identity_id, source_conversation_id, created_at desc)
  where source_identity_id is not null;

create table note_part_versions (             -- EDT-3
  id            uuid primary key,
  user_id       uuid not null,
  part_id       uuid not null,
  text          text not null,
  origin        text not null check (origin in ('chat','app')),
  edited_at     timestamptz not null,         -- when the edit was made (platform time or server time)
  recorded_at   timestamptz not null default now(),
  applied       boolean not null,             -- false = arrived late and did not overwrite (EDT-5)
  source_event_id text,
  foreign key (user_id, part_id) references note_parts (user_id, id) on delete cascade
);
create index versions_part on note_part_versions (part_id, edited_at desc);
```

App-origin versions written by the same session within 60 seconds are coalesced into one row, so rapid checklist toggles do not flood the history (CORE-N17).

## 5. Change log

```sql
create table changes (
  user_id      uuid not null references users(id) on delete cascade,   -- gone with the user (AUTH-U9)
  seq          bigint not null,
  entity_type  text not null,     -- 'note','page','category','reminder','share_link','notification','identity','session'
  entity_id    uuid not null,
  op           text not null check (op in ('upsert','delete')),
  version      integer,
  created_at   timestamptz not null default now(),
  primary key (user_id, seq)
);
```

**Cursor monotonicity (CORE-S3).** A plain sequence would let a transaction that took value *N* commit after one that took *N+5*, so a client that had read up to *N+5* would never see *N*. Instead every write transaction first locks the user's row and increments `users.change_seq`: writes for one user are serialised, so `seq` is gapless and visible in commit order. (The alternative, reading only below a watermark derived from `pg_snapshot_xmin(pg_current_snapshot())`, was rejected because it needs a per-reader watermark; per-user serialisation costs nothing at this scale.)

The change feed returns rows with `seq > cursor`; the cursor is the opaque form of `seq`. Rows are kept 30 days; a cursor older than the oldest retained row returns `410 gone` and the client does a full resync. `NOTIFY` carries only identifiers, never content (see [05](05-realtime-and-jobs.md) §1).

## 6. Attachments and blobs

```sql
create table blobs (
  id             uuid primary key,
  user_id        uuid not null references users(id) on delete cascade,
  backend        text not null default 'pg',     -- CORE-A2
  size_bytes     bigint not null,                -- final size once complete
  chunk_size     integer not null default 262144,
  sha256         bytea,                          -- set on completion (CORE-A5 later)
  complete       boolean not null default false,
  reserved_bytes bigint not null default 0,      -- quota reservation held while uploading (§6.2)
  created_at     timestamptz not null default now(),
  unique (user_id, id)
);

create table blob_chunks (
  user_id  uuid not null,                           -- denormalised so the RLS policy needs no join
  blob_id  uuid not null,
  idx      integer not null,
  data     bytea not null,
  primary key (blob_id, idx),
  foreign key (user_id, blob_id) references blobs (user_id, id) on delete cascade
);
alter table blob_chunks alter column data set storage external;   -- media is already compressed

create table attachments (
  id          uuid primary key,
  user_id     uuid not null,
  blob_id     uuid not null,
  filename    text not null,
  media_type  text not null,
  created_at  timestamptz not null default now(),
  unique (user_id, id),
  foreign key (user_id, blob_id) references blobs (user_id, id)
);

create table user_storage (
  user_id      uuid primary key references users(id) on delete cascade,
  used_bytes   bigint not null default 0,
  reserved_bytes bigint not null default 0,
  quota_bytes  bigint                              -- null = deployment default (CORE-A3)
);
```

### 6.1 Reading

Chunks are fixed size (`chunk_size`, 256 KiB), so a byte offset maps to `idx = offset / chunk_size` and an in-chunk offset by arithmetic. The `io.ReadSeeker` used by `http.ServeContent` fetches one chunk at a time (`select data from blob_chunks where blob_id=$1 and idx=$2`), so memory is one chunk per active download regardless of file size (CORE-A6, CORE-A8, NFR-API4). `Seek` never reads.

### 6.2 Writing and quota (SEC-CNT-6, SEC-API-7)

Quota is enforced by **reserving against the declared `Content-Length`, then reconciling**:

1. Upload requires `Content-Length` (`411` otherwise) and refuses more than the maximum attachment size (CORE-A3).
2. One atomic statement reserves the space: `update user_storage set reserved_bytes = reserved_bytes + $n where user_id = $u and used_bytes + reserved_bytes + $n <= quota returning …`. Zero rows means `413 quota_exceeded`; two concurrent uploads cannot both pass.
3. The blob row (`complete = false`, `reserved_bytes = n`) is created and chunks are inserted as the body streams in, each in its own short statement (memory is one chunk).
4. If the stream delivers more bytes than declared, the upload aborts. On success the transaction sets `complete = true`, `size_bytes`, `sha256`, moves the reservation into `used_bytes`, and creates the `attachments` row.
5. On failure or abort the reservation is released. A janitor job releases stale reservations and deletes incomplete blobs older than one hour, and deletes attachments never linked to a note part after one hour.

Deleting an attachment deletes its blob in the same transaction when no other attachment references it (`delete from blobs where id = $1 and not exists (…)`, chunks cascade), so no blob is orphaned (CORE-A8). Bulk deletion for user removal is done chunk-batch by chunk-batch to keep transactions small (see [03-auth.md](03-auth.md) §4.3).

### 6.3 Deduplication and backend migration (CORE-A5, CORE-A7)

- **Deduplication (Should):** `blobs.sha256` is computed while streaming. On completion, if the same user already has a complete blob with the same `(sha256, size_bytes)` (a partial unique index), the new attachment row points at the existing blob and the new chunks are deleted in the same transaction. Deduplication is **per user only**, and a client can never obtain a blob by claiming a hash (SEC-ISO-9).
- **Backend migration (Should):** `blobs.backend` names the storage backend and all blob access goes through the storage interface. `core admin blobs migrate --from pg --to <backend>` iterates blobs of the source backend, copies each to the target, verifies the checksum, then flips `backend` in one transaction and removes the source copy. Reads stay correct throughout because every read looks at the blob's own `backend`, so migration needs no downtime and no API change.

## 7. Positions inside categories

Order inside a category uses **fractional (lexicographic) keys**: base-62 strings compared with `collate "C"`, with a key generated strictly between two neighbours. Because moving or inserting one note writes only that note's key, two devices reordering different notes never conflict (CORE-S4); integer positions with renumbering would.

- The client sends `before_id` and/or `after_id` (the notes it dropped between); the server reads their keys under the user lock and generates the new one, so clients never generate keys.
- Keys grow slowly when repeatedly inserting at the same spot. When a key exceeds 48 characters the server enqueues a `RebalancePositions` job for that category: under the user lock it rewrites all keys with evenly spaced short keys in one transaction and emits change-log entries; clients refetch the category.
- Pages and categories order the same way.

## 8. Search (CORE-N13)

A generated column cannot work: the searchable text lives in `note_parts` and, for filenames, in `attachments`. Instead:

```sql
create function nk_unaccent(text) returns text
  language sql immutable parallel safe as $$ select public.unaccent('public.unaccent', $1) $$;

create table note_search (
  note_id  uuid primary key,
  user_id  uuid not null,
  body     text not null,                              -- part texts and attachment filenames
  doc      tsvector not null,                          -- to_tsvector('english', nk_unaccent(body))
  foreign key (user_id, note_id) references notes (user_id, id) on delete cascade
);
create index note_search_doc on note_search using gin (doc);
create index note_search_trgm on note_search using gin (nk_unaccent(lower(body)) gin_trgm_ops);
```

A constraint trigger on `note_parts` (insert, update, delete), deferred to commit, rebuilds the note's `note_search` row from its parts and their attachments' filenames, so search is updated in the same transaction as the change (CORE-N13) and no code path can forget it. The query builder turns user input into prefix tokens (`tick:*`), ranks with `ts_rank_cd` and recency as tie-breaker, filters through `notes.state`, and takes snippets with `ts_headline`. A trigram fallback provides typo tolerance (Should).

## 9. Reminders, outbox, notifications

```sql
create table reminders (
  id            uuid primary key,
  user_id       uuid not null,
  note_id       uuid not null,
  due_at        timestamptz not null,               -- next occurrence
  rrule         text,                               -- recurrence (RFC 5545 subset), null = one-off (CORE-R10)
  tz            text not null,                      -- IANA zone the recurrence is evaluated in
  state         text not null default 'pending'
                check (state in ('pending','fired','suspended','done','cancelled')),
  last_fired_at timestamptz,
  claimed_until timestamptz,                        -- lease held by the scheduler while firing (§ in 05)
  created_at    timestamptz not null default now(),
  version       integer not null default 1,
  foreign key (user_id, note_id) references notes (user_id, id) on delete cascade
);
create index reminders_due on reminders (due_at) where state = 'pending';

create table bot_outbox (                            -- Core → bot (BOT-11)
  id                uuid primary key,
  bot_instance_id   uuid not null references bot_instances(id),
  kind              text not null check (kind in ('reminder','notice','lifecycle')),
  user_id           uuid references users(id) on delete cascade,   -- null for lifecycle: holds no user (AUTH-U9)
  external_user_id  text not null,
  conversation_id   text not null,
  payload           jsonb not null,                                -- rendered text, attachment refs, links
  state             text not null default 'queued'
                    check (state in ('queued','claimed','delivered','failed','expired')),
  attempts          integer not null default 0,
  next_attempt_at   timestamptz not null default now(),
  lease_expires_at  timestamptz,
  due_at            timestamptz,                                   -- for 'late' flagging

  finished_at       timestamptz,
  failure_reason    text
);
create index outbox_claim on bot_outbox (bot_instance_id, next_attempt_at)
  where state in ('queued','claimed');

create table outbox_messages (                       -- maps chat messages back to reminders for !snooze / !done
  bot_instance_id uuid not null, conversation_id text not null, message_id text not null,
  outbox_id uuid not null references bot_outbox(id) on delete cascade,
  primary key (bot_instance_id, conversation_id, message_id)
);

create table notifications (                         -- in-app (CORE-R9, AUTH-U11)
  id uuid primary key, user_id uuid not null references users(id) on delete cascade,

);
```

## 10. Sharing

```sql
create table share_links (
  id               uuid primary key,
  user_id          uuid not null,
  note_id          uuid not null,
  token_hash       bytea not null unique,           -- sha256 of a 192-bit random token (SEC-SHR-3)
  created_at       timestamptz not null default now(),
  expires_at       timestamptz not null,            -- always set (CORE-SH2)
  revoked_at       timestamptz,
  last_accessed_at timestamptz,
  view_count       integer not null default 0,
  foreign key (user_id, note_id) references notes (user_id, id) on delete cascade
);
```

A link is valid **only as a live condition** evaluated on every request: `revoked_at is null and expires_at > now()` joined with `notes.state = 'active'` and `users.status = 'active'`. There is no stored "valid" flag and no cache, so dismissing a note disables the link and restoring it re-enables it until the original expiry (CORE-SH5). Expired rows are purged a week after expiry.

## 12. Roles and migrations

| Role | Rights |
|---|---|
| `nk_migrate` | Owns the schema; DDL. Used only by the migration Job. |
| `nk_app` | Core runtime. DML on all tables, subject to row-level security; no DDL, no `BYPASSRLS`; `INSERT`/`SELECT` only on `audit_log`. |
| `nk_bot_matrix` | Bot runtime. Owns its own schema (`matrix_bot`) for mautrix's crypto and sync tables; no access to Core's tables (SEC-OPS-5). |

Migrations are forward-only and backwards-compatible across one release (add columns and tables first, remove later) so a rolling update needs no downtime (NFR-D4).

## 13. Retention

| Data | Kept |
|---|---|
| Change log | 30 days |
| Ingest events | 90 days (bounds how long a replay after bot downtime is recognised; permanent duplicate protection for creations is the unique index `parts_source`) |
| Idempotency keys | 24 hours |
| Expired share links | 7 days after expiry |
| Expired and revoked sessions | 30 days (for the session list and audit) |
| Notifications | 90 days after being read |
| Audit log | Indefinite in v1 (small, content-free) |
| Trash | Until permanently deleted (CORE-N11) |
